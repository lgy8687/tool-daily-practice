## 2. 信息架构（三稿共用）

```
底部导航（4 项，常驻）
├─ 今日  ← 启动默认页，唯一焦点「今日修习」
│    ├─ 主卡：今日 N 遍 + 连续天数 + 主按钮「继续诵读」
│    ├─ 两课大卡（心经 / 道德经）：今日 / 累计 / 天数 → 进背诵
│    ├─ 近 7 日趋势
│    └─ 一句短偈（收尾留白）
├─ 读经  ← 本次新增常驻入口
│    ├─ 经典切换（道德经 / 心经）
│    ├─ 经文白卡（拼音可开关）
│    ├─ 本章导读（折叠全文）
│    └─ 上一章 / 下一章 / 标记读过
├─ 统计  ← 结构沿用 v23
│    ├─ 连续徽章 + 历史最佳
│    ├─ 今日 / 本月 / 累计 三格
│    ├─ 12 周热力格（点格选日期）＋ 折叠编辑入口（在卡内）
│    └─ 近 7 日趋势
└─ 我的  ← 设置 / 字号 / 数据备份

背诵（全屏沉浸态，不进导航）
├─ 选择页：两张大卡
└─ 诵读页：经文垂直居中 + 单一主点击计数 + 轻量撤销
```

**为什么是 4 项、且「背诵」不进导航**

- 读经是**常态浏览任务**，需要稳定、可预期的入口；藏进卡片会让用户每次都要回想「从哪进」。
- 背诵是**全屏沉浸态**，进入时导航会隐藏。若把它做成 tab，会出现「点了底部按钮、底部按钮自己消失」的状态跳变，违反一致性原则。正确做法是让首页主卡成为它的唯一明确入口。
- 4 项在 iOS HIG 建议的 3–5 项范围内，拇指可达且不会挤。

**每屏只有一个主角**

| 屏 | 主角 | 次要 | 唯一主动作 |
|---|---|---|---|
| 今日 | 今日修习主卡 | 两课 / 趋势 | 继续诵读 |
| 读经 | 经文正文 | 导读 / 章节导航 | 标记读过 |
| 统计 | 连续天数徽章 | 热力 / 趋势 / 编辑 | 选日期 |
| 我的 | 设置列表 | 说明文字 | 导出备份 |
| 背诵 | 单一主点击区 | 撤销（弱化） | 记一遍 |

## 3. 符合用户习惯的依据（逐条可验收）

| # | 设计决策 | 依据 | 本方案动作 |
|---|---|---|---|
| 1 | 核心任务常驻导航 | 一致性、可发现性 | 读经升为第 2 个 tab |
| 2 | 首页单屏一主角 | 减少选择成本（Hick） | 主卡唯一深底/大数字，其余降级 |
| 3 | 主按钮全宽 ≥44px 且位于卡片下半部 | Fitts 定律 + 单手拇指热区 | 继续诵读按钮 100% × 44 |
| 4 | 计数「一大一小」不对称 | 高频操作放大、破坏性操作弱化 | 整块点击 +1，撤销只是小圆角按钮 |
| 5 | 点按必有即时反馈 | 系统状态可见性 | ＋1 浮字、数字弹跳、真机触觉，≤0.6s |
| 6 | 编辑入口默认折叠 | 避免误改、可编辑元素一眼可辨 | 折叠在热力卡内，选完日期紧接着改 |
| 7 | 热力格四级 + 当天朱砂 | 1 遍和 10 遍一眼可分 | 保留 v23 实现 |
| 8 | 生僻字只标确定读音 | 不制造错误学习 | 保留 `dao-pinyin.js`，排版保存剥离 `rt` |
| 9 | 全站一个强调色 | 降低视觉噪声 | 三稿均只用一种强调色 |
| 10 | 可访问性 | WCAG | 正文对比度 ≥4.5:1、点击目标 ≥44px、尊重 `prefers-reduced-motion` |

## 7. 我的推荐：A · 静气纸本

1. **气质对**：这是读经工具，不是效率 SaaS。米纸底 + 宋体 + 墨绿朱砂，与「日课」的语义一致，B 的靛蓝偏「任务管理」，C 的黑白偏「代码编辑器」。
2. **成本最低**：`DESIGN.md` v4 已有整套墨绿 + 朱砂 token，A 稿可直接复用，统计页热力四级、连续徽章几乎零改动。
3. **零适应成本**：你在用的 v23 就是这个色系，换 A 只是把首页补齐，不换品牌、不重建肌肉记忆。
4. **可进可退**：A 的结构就是 B/C 的结构。将来想更现代，只换 `--bg / --brand / --radius / --font-title` 四个变量即可，不用重画页面。

**什么时候选别的**：想让「数据激励」成为主诉求、或主要面向新用户 → B；长期只读经文、讨厌任何装饰、想要纯工具感 → C。
